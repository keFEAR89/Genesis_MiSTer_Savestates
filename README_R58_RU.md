## Сборка

Откройте прежний проект C:\FPGA\Genesis\Genesis.qpf и выполните обычную полную
компиляцию. В SS Status будет R58 fix1. Старый RBF в output_files оставлен;
он не является R58. QSF, SDC, seed=2, параллелизм=6 и DDR-контроллер не менялись.
После успешной сборки Package-R58.ps1 проверит свежесть, хеши исходников и timing,
затем создаст архив с Genesis.rbf. Сам скрипт компиляцию не запускает.

## Использование

В главном меню появились Savestate Slot (1–4), Save State и Load State.
Это разовые команды: больше не нужно переключать On/Off.
Выберите слот, нажмите Save State, продолжите игру, нажмите Load State.
Команды закрывают меню. Во время операции новые команды недоступны.

MiSTer Main сам записывает файлы; отдельный скрипт и изменённый MiSTer binary
не требуются. Обычное расположение: savestates/Genesis/<имя ROM>_1.ss ... _4.ss
на используемом MiSTer носителе. При переопределении имени ядра каталог может отличаться.
Файлы привязаны Main к имени ROM; ядро дополнительно сравнивает CRC загруженного ROM
и длину его потока. Чужой ROM или несовместимый формат не загружаются.

После Save State дождитесь сообщения Main «Saving the state» и окончания записи,
прежде чем выключать MiSTer, менять ROM или повторно перезаписывать слот.
Main опрашивает изменения примерно раз в секунду. Busy: No и Slot valid: Yes
подтверждают состояние ядра/DDR, а не успешную запись на носитель: стандартный
протокол не возвращает FPGA подтверждение записи файла или ошибку файловой системы.

Обычный сброс игры больше не стирает файловые слоты. При повторной загрузке ROM
Main переносит имеющиеся файлы в DDR, после чего Load State доступен без нового SAVE.
Save/Load Backup RAM по-прежнему относятся к штатным сохранениям самой игры;
они не нужны для savestate. Load Backup RAM сбрасывает игру, как и раньше.

## Первая проверка на MiSTer

1. Загрузите R58 и ту же игру, выберите слот 1, нажмите Save State.
2. Проверьте возврат состояния через Load State и появление файла _1.ss.
3. Сохраните другое состояние в слот 2 и проверьте независимость слотов 1 и 2.
4. После окончания записи перезапустите ядро и загрузите тот же ROM.
5. НЕ делайте новый SAVE: выберите слот 1 и нажмите Load State.
6. Повторите после выключения и включения MiSTer; проверьте изображение, звук и игру.

Главный критерий этой версии — LOAD старого файла после выключения питания.
Настройки Region, CPU Turbo, Sprite Limit и 6 Buttons Mode должны совпадать с SAVE;
при несовпадении будет Different settings, без импорта состояния.
Существующие ограничения R57 на специальные периферийные устройства/картриджи
сохраняются (в том числе SVP, Pier Solar, multitap, mouse, gun, serial).
Совместимость остальных игр и длительной игры после LOAD ещё не подтверждена.

## Статус и диагностика

SS Status: SAVE seen, LOAD seen, Slot valid, Busy, Error.
После смены слота метаданные перечитываются автоматически. Slot valid здесь означает
совместимый заголовок выбранного слота; полный CRC проверяется при LOAD.
Закройте и снова откройте страницу, чтобы обновить показания.
Different ROM — другой CRC/размер ROM; Different settings — настройки не совпадают.
No saved slot — пустой слот. Invalid header — другой формат/неверный размер.
DDR CRC mismatch — повреждение payload. Import CRC mismatch — ошибка записи
в восстановленные блоки; после такой ошибки ядро делает восстановительный сброс.
Прежние диагностические тесты остаются в Miscellaneous; для обычного SAVE/LOAD
оставляйте их выключенными.

## Формат и порядок публикации

CONF_STR: SS3E100000:40000; четыре области по 0x40000 байт.
Слот N (0–3): физический адрес 0x3E100000 + N*0x40000.
DDR ping в 0x3E000000 не пересекается со слотами.
Все слова little-endian, 64-битные:

| Смещение | Содержимое |
| --- | --- |
| 0x00 | [63:32]=35336 слов по 32 бита тела, [31:0]=счётчик изменений Main |
| 0x08 | 0x5235385300010001 — формат R58 v1 |
| 0x10 | [63:32]=CRC32 payload, [31:0]=141312 |
| 0x18 | [63:32]=длина загруженного потока ROM, [31:0]=CRC32 |
| 0x20 | status[63:0] & 0x00000000860000E0 |
| 0x28 | 141312 байт прежнего payload R57 fix8 |

Файл: 141352 байта, включая контрольное слово. ROM CRC считается по байтам потока
WIDE=1 (сначала data[7:0], затем data[15:8]); это внутренний идентификатор, он не
обязан совпадать с CRC стороннего каталога ROM. Длина учитывает переданные слова.

SAVE сначала обнуляет размер в контрольном слове, сохраняя счётчик. Затем захватывает
и записывает payload, перечитывает его для CRC-проверки, записывает метаданные,
возвращает CPU в игру. Только после успешного завершения меняет счётчик и размер,
что запускает стандартную запись Main. Ошибка SAVE не публикует файл; прежний файл
на носителе остаётся, но DDR-копия этого слота могла быть уже перезаписана.
LOAD проверяет размер, формат, ROM, настройки и CRC до остановки CPU и импорта.
После импорта остаётся прежняя проверка чтением из целевых блоков R57.

Стандартный Main не предоставляет блокировку или подтверждение записи файла:
не перезаписывайте слот во время его записи. Эта версия не обещает атомарную запись
файла при отключении питания. Результат на SD-карте проверяется отдельно от FPGA.

## Проверки до Quartus

Icarus Verilog: четыре полных SAVE/LOAD, повторные LOAD, перезапись, модель
сохранения/возврата файла Main после сброса, неверные ROM/настройки/формат/CRC,
ошибка захвата, ошибка возврата CPU, потерянные импортируемые записи,
команда во время фонового чтения метаданных; известные CRC-векторы ROM.
pyslang: SV-синтаксис и частичная проверка стыковки с VHDL-заглушкой портов.
Проверено неизменное соответствие байтов и конвейеры payload R57.
Это модульные RTL-тесты с моделями DDR и orchestrator, не симуляция всего Genesis.
